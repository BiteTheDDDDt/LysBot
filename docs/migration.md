# 从旧部署迁移到 LysBot

LysBot 使用全新源码仓库。迁移不需要复制旧 Git 历史，也不要求删除聊天记忆。先在独立测试目录验证，生产切换与代码整理分开进行。

## 配置映射

| 旧部署 | LysBot |
| --- | --- |
| `SUPERUSERS` | 选择一个账号写入 `MASTER_QQ` |
| `MODEL_GENERAL`、provider 凭据 | 保留 |
| 专用模型 `MODEL_*` | 需要则保留；留空关闭能力 |
| `MODEL_FALLBACK` | 可保留，也可不填 |
| 向量模型名、维度、revision | 不再填写；内部固定为现有本地 BGE 工件 |
| `GOOGLE_TTS_ENABLED`、`IMAGE_GEN_ENABLED` | 不再使用；由专用模型配置决定 |
| 每日简报／新闻 | 保留开关；新闻依赖简报和搜索 |
| 群名片显示 | 使用 `ENABLE_MODEL_CARD=true` 显式启用 |
| 静音状态和掉线邮件 | 新版移除 |
| 投资通知 | 迁成私人扩展，不包含在公开代码中 |

## 数据与切换

1. 确认实际生产数据库位置和挂载。旧部署可能使用独立命名卷，不能把宿主机的旧 `data/history.db` 当成当前生产库。
2. 在运行库所在系统内使用 SQLite backup 生成一致性备份，另备份配置、图库、模型和 NapCat 登录状态。不要直接复制正在写入的 DB 文件作为备份。
3. 测试实例使用关闭的数据库副本和虚构／独立配置，核对历史、记忆、来源与检索。不要让新旧 bot 同时消费同一个 QQ 连接或写同一份运行数据。
4. 基于本仓库 Compose 文件准备生产 override，映射原数据库卷及 `/app/data`，需要时保留 `LLM_CHAT_DATABASE_PATH`，接入原网络、人设和私人插件。使用本仓库 Dockerfile 构建镜像；沿用原 NapCat 时只部署 LysBot 的 bot 服务，避免创建第二个 QQ 实例。
5. 停止旧 bot，生成切换前备份，启动 LysBot，检查数据库、OneBot、实际回复、检索和已启用任务。不要恢复一次旧快照来覆盖切换后的新增消息。

`data/`、`.env`、私人扩展和 QQ 登录状态都属于私有部署资料。它们可以继续供生产使用，不应进入公开仓库。

保留旧镜像和原配置用于回退。新版本没有主动改写业务表结构的迁移脚本，但自动初始化与索引维护仍可能写入数据库；生产切换前必须完成副本验证，不能仅依据离线测试通过。

首次迁移完成后，日常更新按 [统一构建与更新流程](ai-operations.md#构建与更新) 执行。生产目录只承载部署配置和私有数据，核心代码持续使用开源仓库。
